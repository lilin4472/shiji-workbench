# 识机 V1：产品逻辑链与数据流

> 唯一现行需求基线：自 2026-09-09 起，本文件是识机 V1 唯一持续更新的需求设计文档；不另建 V2 或平行需求稿。其他冻结稿、技术决策和开发日志只作历史或实现证据，不得覆盖本文件。

## 1. 文档作用

本文档是识机 V1 各模块开发、数据验证和真实能力接入的共同依据。它回答四个问题：

1. 用户在左侧输入什么，右侧各模块展示什么。
2. 数据经过哪些步骤，哪些对象必须跨模块复用。
3. 什么操作会新增数据、改变判断或触发付费调用。
4. 每个环节应测试什么，避免只测试局部技术而没有验证产品结果。

本文档只定义产品业务链，不新增服务器、账号体系、云端数据库、数据导出或通用工作流引擎。

## 2. 总体原则

- 一个项目只有一个稳定 `Project/Opportunity ID`；时间链、政策链、企业风险、产业链、获客、行动和订阅都引用同一对象。
- 搜索结果不是事实，网页正文也不是自动成立的结论。必须保留来源、转载关系、关键标识和判断依据。
- 来源不按“官方是真、商业是假”二分。网站信誉、原始出处和具体内容分别评估。
- 所有合理来源都可以用于发现；能否推动项目阶段或工商结论，由证据用途和强度决定。
- 模型负责归纳、匹配和解释，不负责凭空补事实；确定性状态由规则和证据共同决定。
- Key、搜索结果、证据、项目、报告和订阅保存在本机。前端不读取明文 Key。
- 天地图服务端 Key 与网页端 Key 分离：地址解析、POI 与距离计算只在 Electron 主进程使用服务端 Key；真实底图只在附近地图页面按需读取网页端 Key，两个 Key 不混用。
- 用户主动搜索和订阅复查共用同一查询、缓存、证据处理与项目合并链，不建立第二套跟踪逻辑。
- 普通招标搜索只生成基础项目结果和招标详情，不自动连带运行时间链、政策链、产业链、企业公开风险或获客；扩展分析必须由用户针对已选项目或主体主动启动，并在启动前显示对象范围和预计调用量。
- 用户正常启动桌面产品时只能存在一个识机实例；生产入口不得自动注入 Mock 商机、企业、政策、关系、联系方式或行动。Mock 只能由明确的开发模式启用并显示“开发预览”标识。
- “替换硬编码”专指逐步删除 Mock 业务结果、固定企业/关系/联系方式、占位统计和只为演示存在的跳转；阶段枚举、证据阈值、安全上限、字段映射等稳定规则属于正式代码，不为追求“零硬编码”改成不必要的配置系统。
- 一个模块只有完成“真实任务 → 能力调用 → 原始来源 → 确定性检查 → 统一对象 → 本地保存 → 界面展示/失败状态”才算跑起来；只有真实搜索但右侧仍展示 Mock，不算接入完成。
- **2026-09-14 导航收敛决定**：左侧一级导航只保留「商机推演」与「商机情报」两个支柱组。GEO 诊断、任务模式「自动识别」、附近商机「个人机会」Mock 卡片与工具栏「计量」入口已从产品删除（GEO 与商机主线无关且真实执行器从未接入；自动识别与深度雷达共用同一招标数据源，其“任意条件搜索”职责由商机雷达的自由输入框承接；个人路线由商机推演承接；计量按第 12 项既有裁决删除）。分析类视图（时间链/政策链/产业链/公开风险/获客/行动）保留为选中项目后的工作区页签，不占一级导航。
- **2026-09-15 门禁放权与门户拦截**：正文进入模型的条件由“主体+阶段双命中”放宽为“主体或阶段任一命中”，缺失项交由 DSH 结合正文判断（输出仍受证据约束，不得编造正文外字段）；机器不再预判“合格/候选”，未结构化来源一律称“来源线索”，是否放入项目库由用户打开原文决定。新增门户首页硬拦截：标题/域名含平台·门户·首页词且无项目编号、截止时间、附件的页面绝不进入模型。地图绘制服务半径圆环与三类图钉（中心/招标项目/POI）。POI 搜索按官方规范实现（queryType=3、pointLonlat、start/count 必填、半径≤10km、单次 1 调用）并保留 IPC 与测试，但按 2026-09-15 用户决定从附近招标页移除入口，延后至商机推演模块接入。总览与证据措辞统一用“搜索结果/来源线索”，不再使用“候选机会”。旧本机状态停留在 `geo`/`metering` 视图时自动回到机会总览；全新安装默认落在「商机推演」。
- **2026-09-21 搜索对象与行动门禁收口（0.2.6 / 契约 16）**：平台首页、栏目页、多项目列表、正文未读取来源只作 `SearchHit/EvidenceRecord`，不再兜底转成 `Opportunity`，旧版已落库的结构性来源卡在启动时回迁为证据线索。项目拖入行动清单只加载本机项目，不自动触发搜索或模型；时间、政策、产业、风险、获客只有在当前项目与主体上存在“部分完成/已完成”运行记录及对应结果时才可以生成行动。未运行模块显示“去补充XX链”，点击只导航并选中项目，仍由用户确认预计调用量后手动启动；获客未满足产业链依赖时先导航到产业链。
- **2026-09-21 双搜索入口纠偏（0.2.8 / 契约 16）**：商机雷达与附近招标的“按以上条件运行”和自由输入“运行”是两条明确入口。条件入口只采用上方已保存条件，跳过 DSH 意图改写；自由入口才把原文交给 DSH，并允许原文明示要求覆盖条件栏。新任务开始即清空上一轮未归档可见结果和当前选中项，禁止用旧地区结果伪装本轮结果；雷达返回后再执行本机画像硬门槛，已明确地域或专业冲突的项目不进入雷达卡片，地址等字段未知的项目仍保留为待核验。
- **2026-09-21 搜索污染门禁（0.2.10 / 契约 17）**：两个入口共享同一套正文门禁与项目结构，但不自动合并执行。条件入口只读条件栏；自由入口由 DSH 理解原文，并仅用未被原文提及的条件作背景。豆包返回的平台首页、多项目聚合页、企业维度“招标中标信息”历史聚合页，以及“哪里查 / 实操指南 / 查询渠道 / 平台盘点”等编辑型文章只能保留为内部检索参考，不得生成项目卡；右侧无具体项目时也不再把这些页面伪装成项目来源卡。商业招采网站不按域名一刀切，具体公告正文仍可进入结构化流程。用户明确选择具体阶段时，正文已确认属于其他阶段的公告只作参考，阶段未知的具体项目仍可进入待核验；异常、终止、废标和流标公告不生成可跟进项目卡。“招标人”只用于主体识别，不再被误判为招标阶段；搜索命中的具体公告标题优先于商业站点直读后的通用页标题。
- **2026-09-23 附近企业商机具体项目门禁（0.2.18 / 契约 18）**：附近企业商机仍复用豆包搜索、正文读取、DSH 结构化和统一项目卡管道，但比普通商机雷达多一道用途门禁：只有识别到项目阶段，并同时取得明确阶段公告措辞、项目/文号、投标截止时间或附件之一，才可生成附近招投标项目卡。仅能识别企业、政府或事业单位主体的介绍页、新闻页和名录页保留为搜索证据，不得伪装成招标项目；该收紧不改变商机雷达此前确定的宽召回策略。
- **2026-09-23 真实搜索验收与字段边界（0.2.26）**：雷达/附近招标的条件与自由入口各完成一次不命中缓存的豆包搜索，并走 DSH 结构化；每条路由目标 3 条，实际均返回 3 条，其中附近自由入口包含 2 条结构化项目和 1 条已标明的来源线索。真实结果复核发现地址候选可能与同一正文段后续的招标范围、规模、工期等字段粘连；地址抽取必须在这些字段标签处截断，不可把完整项目描述送入地图定位。真实矩阵报告在开发状态记录中；该验收不代表地图经纬度、半径或全部分析模块的真实联网数据质量已全项验收。
- **2026-09-23 分析模块范围跟随总览勾选（0.2.19 / 契约 19）**：时间链、政策链、产业链、公开风险、获客按总览当前勾选的全部项目逐个执行并逐项目展示，不设三个项目上限；启动前显示随项目数量线性增加的预计调用量。行动继续按底部行动清单中实际加入的全部项目展示与跟踪。
- **2026-09-23 多项目模块页去除单项上下文卡（0.2.20 / 契约 20）**：分析模块和附近商机不再在页面最上方展示只跟随当前选中项的项目上下文卡。未启动分析的单项范围仍显示项目名，多项范围显示“N 个项目待分析”；具体项目名单由模块内完整范围列表展示，结果视图保留“本次分析对象”及全部项目卡。
- **2026-09-23 对比篮字段状态与项目准入分离（0.2.26）**：将项目加入对比篮或分析范围只表示用户选择该项目作为工作对象，不代表用户确认其事实或证据已经核验；“待核验”不得作为普遍流程阻拦。对比页按项目对象与关联本机证据展示主体、金额、地址、截止时间和阶段；来源提取候选须标为未确认，缺失值应具体区分“正文未提取”“未取得阶段证据”“尚未启动查询”。距离只服务附近搜索的半径判断与地图定位，不作为对比指标，因为项目未必共用同一搜索中心。公开风险仅显示对应项目真实分析结果，零命中不表示无风险；点击对比栏内某项目风险时，只导航到该项目在总览中的选择及公开风险模块，不自动发起付费分析，也不清除其他已选项目。来源/正文污染门禁、时间链证据门槛、获客产业链依赖及行动模块分析完成门槛继续独立生效。
- **2026-09-23 附近发现与总览选择解耦**：附近招标搜索完成只更新“本次附近结果/来源线索”，不自动加入总览；用户逐项目勾选“加入总览”后，总览才出现该项目。取消勾选只移出总览，不删除附近卡片或本机项目，也不得因此弹出旧来源卡。归档、忽略、删除仍按项目生命周期生效。新附近搜索替换附近可见结果，不清除用户已选总览项目或管理篮引用；旧版最近一次附近任务的自动勾选在首次加载时迁回附近结果，已用于分析、追踪或管理篮的项目继续保留总览选择。雷达继续保持独立结果集与显式加入总览。对比篮只消费用户拖入的项目引用，按项目本机字段和证据显示摘要，不为了生成摘要触发额外搜索或模型调用。
- 自动化测试、类型检查和构建通过只证明工程基础没有明显回归，不能代替用户验收。任何达到可操作状态的阶段，必须在生产模式按真实用户路径完成“左侧输入/条件 → 点击运行 → 右侧首层结果 → 二次详情/模块 → 保存或失败反馈”的实机验证，才能标记完成。

## 3. 产品总链

```text
左侧商业条件 / 对话补充
  → Task（一次任务）
  → SearchPlan（阶段、地区、专业、金额、预算）
  → SearchRequest（供应商可执行请求）
  → SearchHit（标题、摘要、网址，不等于事实）
  → DocumentArtifact（网页正文、PDF、截图、人工导入材料）
  → Provenance（原发布者、转载者、原文链接、文号、项目编号、日期）
  → EvidenceAssessment（证据强度、可用于何种判断、仍需核验项）
  → Company / Project / Opportunity（统一业务对象）
  → Timeline / Policy / Industry / Risk（分析结果）
  → Lead / Action / Compare（用户可执行结果）
  → WatchRule（订阅项目与上次确认节点）
  → 增量搜索新证据
  → 合并回同一 Project，重新计算分析和展示
```

GEO 诊断支线已于 2026-09-14 从产品中整体移除（数据链、视图与任务模式一并删除）：它是品牌 AI 可见度体系，与商机主线行业隔离，且真实多模型执行器从未接入。旧本机 `shiji.geo-subject.v1` 数据不迁移也不删除。若未来重启该能力，按独立产品另行立项，不在本文件范围内。

## 4. 核心数据对象与唯一职责

| 对象 | 唯一职责 | 当前状态 |
| --- | --- | --- |
| `BusinessProfile` | 保存用户长期商业能力画像，包括主体性质、规模、行业、专业、资质、人员/设备、经验、资产与履约边界、服务区域和风险偏好 | 已与单次搜索条件拆成独立契约；档案填写、本机持久化和深度雷达确定性匹配已接入 |
| `OpportunitySearchCriteria` | 保存自动识别/附近企业单次任务的目标单位/项目关键词（可选）、地区、半径、金额、类型、阶段、时间窗口和期望候选数 | 目标单位/项目与 5/10/20 三档已贯穿豆包请求、缓存键和 DSH 输出上限；自由输入明确的 1–20 个项目时，本次目标数量与证据召回池单独计算；深度雷达不得读写该对象 |
| `DeepRadarSearchTask` | 保存深度雷达本次任务，只携带长期 `BusinessProfile`、雷达本次原文和由二者形成的可执行搜索条件 | 已建立独立任务类型、搜索用途、本机结果集和选中状态；待真实桌面路径验收后确认完成 |
| `Task` | 记录一次用户任务及运行状态 | 已有 |
| `SearchPlan` | 把业务条件转成阶段查询、调用上限和缓存时效 | 已有基础 |
| `NearbySearchPlan` | 以用户设置地点和个人/企业受众生成独立附近搜索任务 | 企业任务与搜索用途已建；个人正式任务待建 |
| `SearchRequest` | 某个搜索供应商真正执行的统一请求 | 已统一 |
| `SearchHit` | 保存供应商返回的候选网址、标题和摘要 | 已有基础 |
| `DocumentArtifact` | 保存抓取或导入的网页、PDF、图片及处理状态 | 本地 TXT/HTML/文字 PDF 已解析；机会任务已接静态网页正文，JS 页面与 OCR 待接 |
| `Provenance` | 记录原始发布者、转载链和关键文档标识 | 候选提取及分级规则已有；真实网页样本验收待做 |

| `Company` | 企业或机构主体，承载工商公开信息与关系 | 已建立独立本地对象索引；主体消歧和工商信息待后续补齐 |
| `Project` | 项目本体、名称别名、地区、主体、编号和阶段事件 | 已建立独立本地对象索引，优先按项目/采购编号跨阶段复用；完整阶段合并待清单第 4 项 |
| `Opportunity` | 项目与用户能力匹配后的可跟进对象；主体名称与正文项目地址候选随对象保存，金额/距离/截止日可明确为待核验 | 已接真实搜索结构化入口及企业附近本地距离门禁；项目地址抽取在公告地址字段后遇到“招标范围/项目规模/工期”等新字段时必须截断，不能把相邻业务正文作为地址送去地理编码 |
| `OpportunityCatalog` | 在本机统一保存机会正文对象、总览已选集合、附近本次发现集合、各自来源索引及当前/归档/不感兴趣状态；状态不复制项目和证据 | 已接入并兼容迁移旧搜索结果；项目跨来源合并仍由稳定 `Project ID` 后续完善 |

| `ContactPoint` | 保存公开材料观察到或用户确认的企业/个人触达信息及其来源 | 已接真实定向提取、字段语义复核、原文与观察时间；缺失保持缺失 |
| `LeadCandidate` | 从同一关系图派生获客对象、理由、优先级与可核对的触达渠道 | 已由产业链真实节点派生；联系人、邮箱、电话、公司地址分列独立展示，不做无证据配对 |

### 5.0 输入契约、自由输入与运行反馈

所有带自由输入框的模块都遵守同一条输入链，不把自然语言直接广播给其他模块：

```text
自由输入 + 当前模块条件
  → DSH 模型先读取完整原文与条件，识别主体、项目、地区、时间、金额、阶段和事项
  → 生成本次模块任务（IntentEnvelope）
  → 展示解析结果、条件关系和预计调用
  → 用户确认后只运行当前模块
  → 将结果写入当前模块对应卡片
  → 其他模块只显示可继续分析入口，不自动调用
```

- 按用户最新要求，自由输入必须先交给模型理解，禁止以前端关键词/正则替代语义理解。界面告知“本次明确输入优先，未提及项沿用条件”；模型必须完成一次语义合并并返回字段完整的最终条件，程序校验后整套采用，不再把旧条件二次拼接回来。任何字段缺失或结构矛盾都停止搜索，不能静默沿用旧值。该最终条件只改变本次任务，不覆盖保存的设置。有歧义时先澄清，不得猜测后启动无关搜索。本机规则仅负责结构、预算、安全和证据检查。
- 模型理解失败时明确停止，不得退回旧条件搜索。模型生成的查询保留固定字段之外的要求（例如月份、排除项、资格要求）；工商意图进入风险专项入口，不能误用招标来源查询，也不能自动启动所有扩展模块。
- 用户完全不设置条件也可以直接自由输入。系统使用已识别的主体/项目/关键词执行当前模块，缺失字段保持“未提供/待核验”，不能因为条件为空而回退到 Mock 或无关默认数据。
- 自动识别是入口路由，不是全局广播。它可以识别招标、中标、工商、行政处罚、公开风险等事项，并在右侧按事项类型放入对应结果卡；时间链、政策链、产业链、获客、GEO 和深度雷达只在用户明确点击对应入口后启动。
- 自由输入产生的结果只写入本次任务和对应模块结果，不修改其他模块的长期画像、筛选条件或缓存键；长期配置只有用户在相应设置区明确保存才改变。
- 首次运行前必须告知用户：本次识别出的条件、硬/软条件关系、预计搜索/模型调用、可能产生的费用以及不会自动启动的模块。
- 搜索和整理必须显示阶段性加载状态，不伪造固定倒计时：`解析条件 → 搜索公开来源 → 读取正文 → 核对主体/事项 → 整理结果卡片`。同时显示预计/实际调用、缓存命中、部分结果、超时或失败原因。
- 当前模块必须有明确的空结果、部分结果和失败态。来源不足时显示“未取得/待核验”，不得用其他模块的结果填充当前卡片。

### 5.1 基础搜索数量与招标详情

- 用户可以反复修改左侧条件和补充意图；每次点击运行只使用当前锁定条件和本次补充，不把历史对话无限叠加到新任务。
- 左侧保留可见的“目标单位 / 项目关键词（可选）”条件。用户在条件栏设置时，该值进入 `OpportunitySearchCriteria`；用户在本次自由输入中明确新增、修改或取消目标时，DSH 在本次最终条件中按原文优先覆盖，并进入 `SearchPlan`、豆包查询和缓存键，但不得反向改写已保存条件。DSH 的结果整理阶段只能处理搜索已经取得的来源，不能在目标对象没有进入查询时事后补救。
- 单次自由文本最多 300 个中文字符；条件栏“期望候选数”提供 5、10、20 三档，默认 10；自由输入可在本次任务明确要求 1–20 个项目并覆盖输出目标。系统不得因为自身正文解析、金额/时间门禁或 DSH 结构化失败而丢弃真实来源：来源不足时继续保留为“待核候选”，与“已核验”分层展示；只有搜索服务实际没有第二条真实来源时才明确提示来源不足，禁止编造项目或用 Mock 数据补足。
- 搜索结果第一层保持简洁，只展示项目、招标主体、金额、阶段、截止时间、专业、简要概述和来源状态。用户点击任何招标卡后，必须进入完整招标详情；不能要求用户先运行时间链、政策链等扩展模块才能知道如何投标。
- 总览的选中项目按“当前项目大标题 → 当前主体与证据摘要 → 扩展分析入口 → 候选机会列表”排列。主体与证据不得在窄工作区掉到全部候选之后；摘要只显示主体、来源等级、公告标题和详情入口，完整字段仍读取同一证据并进入全屏招标详情，不复制第二套详情数据。
- 招标详情至少覆盖：招标/采购主体与代理机构、项目范围和标段、预算/控制价、投标资格、联合体要求、报名/获取文件方式、保证金、投标截止与开标时间、评审方式、项目地址、公开联系方式、公告原文、附件下载以及缺失待核验项。字段必须来自公告正文、附件或用户导入材料；没有信息时明确显示缺失，模型不得补造。
- 招标详情中的“投标要点/操作清单”只能整理已取得的资格、时间、材料和提交要求，并链接回原文或附件；它不代替正式招标文件，也不承诺用户具备投标资格。

### 5.2 深度雷达是能力画像匹配

- 深度雷达不是普通搜索换一个名称，也不能与机会总览继续共用同一套条件和结果页面。
- 深度雷达使用独立 `deep-radar-search` 任务、`deep-radar` 搜索用途、本机结果集和选中对象。它只读取用户长期能力画像与雷达本次输入；不得沿用自动识别的目标单位、目标项目、地区、金额、阶段、当前候选或当前选中主体。
- 用户长期能力画像至少覆盖：主体性质与规模、行业与专业、资质、人员/设备、历史项目经验、资产和现金流/垫资边界、服务地域、可承接金额、并行履约能力、合作伙伴能力与风险偏好。相关数据由用户在本机填写和修改，模型不得推断为既有事实。
- 雷达本次补充条件只在雷达任务内生效，不读写自动识别的 `OpportunitySearchCriteria`。先用硬性条件排除明显不适配项目，再对资质、地域、金额、经验、履约、风险和时机给出分维度解释；总分不能掩盖任一硬性不满足项。

### 5.3 扩展分析必须由用户主动启动

- 机会总览不显示尚未运行却带有结论或数量的时间链、政策链、产业链和公开风险索引卡；现有“政策同向”“识别若干节点”等预填结果必须删除。
- 模块导航可保留。首次进入模块时显示当前项目/主体、尚未分析、预计调用范围和“启动分析”按钮；状态统一为未启动、运行中、部分完成、已完成、失败或结果已过期。
- “启动分析”是一次明确任务，不使用会让用户误解为今后自动执行的永久开关。只有时间链的“订阅跟踪”属于持续开关，并遵守缓存与启动时检查规则。
- 基础搜索可展示最多 20 个候选；扩展分析默认处理当前选中的 1 个招标主体，批量最多选择 3 个主体。同一主体对应多个项目时按稳定企业 ID 去重，并复用仍在有效期内的政策、风险、产业关系和联系方式结果。
- 时间链、政策链和企业公开风险可独立启动；产业链先形成关系图，获客再消费同一关系节点并按用户选择补充公开联系方式。产业链未运行时，获客必须提示依赖关系，或明确提示本次将连续运行的模块和预计成本。

### 5.4 附近商机是独立业务搜索路由

附近模块不能继续把“全局机会列表换成地图”当成真实实现。用户先设置地点，再明确点击个人或企业；两次点击产生不同任务和数据结果，但底层继续复用同一 `SearchPort`、缓存、正文读取和本地证据仓，不复制供应商适配器。

```text
地点 + 半径 + 用户主动点击
  ├─ 企业 → NearbyEnterpriseTask
  │          → 附近招投标/采购搜索
  │          → 正文、主体、阶段、金额、截止日期与出处门禁
  │          → Project / Opportunity + 本地地理距离
  └─ 个人 → NearbyPersonalTask
             → POI/客流/品牌/学校/餐饮等地理热点
             + 当地政策与经营限制
             + 公开自媒体、案例报道和个体生意模式
             → PersonalOpportunityRecommendation + RiskNotice
```

- 企业附近机会属于项目证据链，必须保留招标主体、金额、专业、阶段、概述、原文和待核验项；距离只能由本地地图/坐标计算，不能让模型估算。
- 企业附近已使用独立 `nearby-enterprise-search` 任务与 `nearby-enterprise` 搜索用途，但仍复用统一搜索适配器、正文读取和机会门禁。正文确定性提取“建设地点/项目地址”等候选，DSH 只能逐字选择这些候选；天地图服务端接口将用户中心与项目地址转为坐标，距离由本机 Haversine 计算。只有两端坐标都存在时才执行半径过滤；地址缺失、定位失败或达到单次地址预算时保留在列表并显示待定位，模型不得估算距离。
- 附近地图必须覆盖本次全部搜索结果（包括未通过结构化、作为来源线索保留的候选），不得只画已定位的前几条。点位分两级：公告正文明确项目地址的坐标优先；地址缺失时使用正文确定性提取的招标/采购主体名称补定位。同一主体只发一次地理编码，同一地址导致的重合点位只在地图上做错开显示；主体名通过点击/悬停图钉的浮层显示，不再常驻地图列表。未识别主体或定位失败时，在该主体没有可信坐标的前提下只在中心附近生成明确的“位置待核验”图钉，不冒充真实点位；右侧列表继续逐条保留并显示待核原因。地图图钉、半径圈、容器与图例颜色必须读取同一套冷/暖 tokens，两种主色切换后同步变化。地图中心使用本次任务最终采用的地址与半径：模型自由输入返回的 `interpretedCriteria` 只作用于本次地图和搜索，不回写用户保存的条件栏；条件栏仍由用户主动修改。

- 个人附近机会属于建议链，不写入项目时间链或工商信用。公开自媒体不设官方白名单，可广泛用于发现经营模式、选品和运营标准，但必须显示来源、发布时间、地域适配、样本偏差、平台营销和经营合规等风险；它只能形成参考建议，不能包装成收益承诺。
- 切换个人/企业不自动复用另一侧结果，也不在页面加载时付费搜索。相同地点和条件先查本地缓存，用户主动刷新才决定是否新增调用。

### 5.5 产业链与获客共用一张关系事实图

产业链至少包含两类不能混淆的关系：

1. 集团组织关系：招标方的上级集团、母公司、子公司、分公司和其他可确认控制/隶属主体。
2. 业务产业关系：上下游供应商、招标代理、承包商、联合体成员以及以往投标方/中标方。

统一数据流如下：

```text
Project / 招标主体
  → 集团组织与历史公告定向搜索
  → 正文读取、主体消歧、关系类型与出处提取
  → EntityRelationship（方向 + 类型 + 证据 + 置信状态）
  → 产业链图展示
  → LeadCandidate 排序
  → 获客建议（联系人角色、接触理由、渠道、下一步）
```

获客模块不再独立重复搜索一套“潜在客户”。它首先消费产业链的同一批节点和关系证据，只在用户需要公开联系方式时进行受限补充搜索。A/B 关系可作为较强关系，C/D 仍可展示为“关系线索/待核验”，不得因为线索放宽就把集团控制、供应关系或历史中标关系写成确定事实。

联系方式允许来自企业官网、公告原文、可信转载中可追溯的公开字段或用户自行录入。每个 `ContactPoint` 必须绑定企业、来源证据、联系人/部门标签、原始值和观察时间；模型只能从已读取文本中抽取、规范化和去重，不能猜测手机号、邮箱、姓名或职位。来源中没有联系方式时，图谱节点和获客卡片统一显示“公开联系方式待提取”，不以通用客服号码或模型推断填空。

### 5.6 政策链采用三级传导并给出预测窗口

- 政策链固定按三个有效层级组织：国家级、省级、市级。普通省份展示“国家 → 省 → 地级市”；直辖市为保持三层业务含义，展示“国家 → 直辖市 → 区县/功能区”，不得重复制造一个不存在的省级节点。
- 每层至少保存发布机关、政策/预算文件、适用行业或项目、资金或任务传导方向、生效/执行时间、关联主体及来源证据。国家预算或政策方向不能仅凭层级关系直接推定已拨付到某个招标单位。
- 预测必须同时参考能够取得的预算下达/专项资金分配、地方实施计划、招标主体职责、在建或拟建项目和历史采购节奏，输出“下一可能招标节点、可能时间窗口、依据、置信度和需要继续观察的信号”。只有正式采购意向或公告可以形成确定节点；其他结果统一标记为预测性建议，不能写成确定招标日期。

### 5.7 V1 不设独立综合研判模块

- 招标详情回答“这是什么项目、谁招、如何投、何时投、需要什么材料以及附件在哪里”，只读取公告、附件和证据对象，是用户从结果卡片进入的事实详情层。
- 深度雷达回答“该机会是否适合当前用户、为什么匹配、哪些硬条件不满足以及还缺什么用户资料”；时间、政策、风险、产业和获客分别保留各自的专项判断；行动指南把用户选中的真实结论转成下一步。
- 单独设置“基础报告/综合研判”只会重复深度雷达、招标详情和专项模块，因此从 V1 导航、路由和数据对象中删除。总览以后可以展示用户已经主动运行过的模块短摘要并链接回原模块，但不得为生成摘要新增调用，也不得显示未运行模块的预填结论。
- 如果以后确有交付或分享需求，可以在当时另行评估“生成项目简报/PDF”这一输出动作；它不是常驻分析模块。本期数据导出已排除，不提前建设。

### 5.8 工商档案采用固定外壳、动态内容

- 工商基础信息与行政处罚、经营异常、严重违法失信、失信被执行等风险事项必须分开展示。基础区优先提取统一社会信用代码、法定代表人、注册资本、成立日期、登记状态和注册地址；字段缺失保持空白，模型不得补写。
- 右侧工商档案允许输入企业完整名称和不超过 300 字的本次关注事项，例如时间范围、股权/法定代表人变更、司法案件或特定处罚。左侧“自动识别”检测到明确工商意图时只负责预填并打开该模块，必须由用户确认后才产生豆包调用；普通招标搜索和深度雷达不得暗中连带付费查询。
- 结果使用一张可伸缩的动态档案卡：外壳固定为主体、基础信息、本次关注事项、公开风险事项、来源与更新时间；内部区块随用户问题和实际搜索结果增减。后台可以保存最多 20 条证据池，前台默认只展示筛选后的重要事实及其原文链接，不要求用户逐条人工筛选。
- 每个风险事项必须尽量展示“具体内容/事实摘要”：处罚原因或违法事实、金额、日期、处理结果、异常/失信状态等只从来源正文或摘要截取，并在该事项标题下绑定来源链接。权威页面需要付费、登录或验证码时，不阻塞用户；相关商业页面、媒体转载和公开摘要可以作为“相关参考”并明确不作为推荐或最终判断。原来的全局 20 条来源列表不再作为前台结果，证据必须按事项归类。
- 豆包负责检索公开网页；自动识别的自由输入先原样交给 DSH 意图层，由 DSH 返回本次条件和目标数量，再进入豆包检索；DSH 随后只对已经取得且可追溯的来源做结构化归纳，输出事实、可能过期和未取得三类信息，不做企业好坏或“是否失信”的综合判决。识机本地层只负责 schema 校验、金额/时间证据门禁、证据绑定和候选保留，不用关键词正则替代用户意图理解；意图层失败时透明退回已设置条件，不伪造解析结果。无 DSH 时仍可显示确定性提取结果，但界面必须如实显示本次模型调用为 0。
- 国家企业信用信息公示系统、信用中国、法院和政府来源权重最高；企查查、爱企查、启信宝、天眼查以及主流媒体等信誉较高的商业来源可直接进入用户参考卡并标注来源性质，不再一刀切丢弃。登记快照还必须满足“登记类来源或信誉工商平台的主体专属资料页”条件，不能从采购公告或新闻中把另一家供应商的代码、法定代表人和地址抄给当前主体。任何来源仍必须核对主体角色，不能把申请执行人、原告、举报人或采购公告中的供应商资格条款误记成被查询主体的不良记录。
- 人工复核不是常规工作流。只有主体同名、责任角色冲突、日期/状态矛盾或来源互相冲突时才出现“存在歧义·复核”；普通结果由后台过滤、去重和归类后直接展示。
- 政府机关不是企业，不套用企业工商五项；事业单位可按统一社会信用代码和法人登记信息形成机构档案。主体类型的完整显式切换与对应查询模板仍列入本模块后续闭环，禁止仅凭名称静默猜测后写成确定事实。
### 5.9 时间链清单、关注与对象管理收口（2026-09-15 用户实机口径定稿）

本节为 2026-09-15 用户实机反馈后的口径变更，优先级高于第 5.3 节中与本节冲突的描述。

1. **时间链改为清单口径。** 一次搜索得到 N 个结果，时间链页必须给出 N 条时间链，而不是只显示当前选中项目的一条。首层为清单（项目 / 主体 / 当前已确认阶段 / 最近节点 / 下一节点或待核验 / 证据数 / 订阅状态），点击某行展开该项目的七阶段节点；原"只跟当前项目"降级为默认展开项。清单渲染只读本机已有阶段证据，不新增任何搜索或模型调用；没有任何阶段证据的项目显示"未取得阶段证据"，不留空白、不预填。
2. **对象管理收口。** `DropBucket` 的「重点跟进」此前没有落地视图（点开回落总览），现合并进 `ProjectWatch`（关注）。拖入「跟踪」＝为该项目建设或激活 `ProjectWatch`，并打开关注列表页；对象管理栏只保留「对比篮」「行动清单」两个拖拽桶，不再保留第二个"跟踪"数据源。**实现口径（2026-09-15 落地）**：管理栏保留「追踪」落点，但它不写入 `ManagedBuckets`：拖入或点击都直接创建/激活 `ProjectWatch` 并打开关注列表页（旧实现是 focus 桶无视图、点开回落总览）。「对比篮」「行动清单」仍是真正的拖拽桶。
9. **拖拽入口唯一性与可放置反馈（2026-09-15 用户要求）。** 只有**总览页的当前结果卡**可以作为拖拽源（卡片本体与右侧把手）；附近招标列表、时间链、政策链、产业链、公开风险、获客、行动、项目库一律不提供拖拽源，避免同一对象在不同模块出现第二套拖拽语义。拖拽经过对象管理区时必须给出"可放置"反馈（`dataTransfer.dropEffect` 与高亮），不得出现红圈斜杠禁止光标；左侧对话栏的"拖动入口只在总览页开放"提示与之对应。
10. **放下后不强制跳转。** 把对象拖入「追踪」「对比篮」「行动清单」后**保持当前视图**，只做状态写入与一行结果提示；查看列表由用户点击对应落点进入。原因：强制跳转会让用户无法连续拖入第二个对象（2026-09-15 实机问题）。
11. **关注计数与取消关注。** 底部「追踪」徽标显示**活动订阅数**（`ProjectWatch.status === 'active'`），不再读取历史桶数据；关注页每条订阅必须提供"取消关注"（删除该 `ProjectWatch`，不再参与复查，时间链页订阅态同步消失）与"暂停/恢复"，并显示复查周期与下次检查时间。
12. **模块统一分析模式（对应用户第 4 点口径）。** 时间链/政策链/产业链/公开风险/获客/行动遵循同一结构：**模块页 = 项目选择器 + 启动分析 + 结果区**。
    - 选择器的候选来自本机结果集（`opportunities`），默认勾选"总览当前选中项目"，支持全选与多选；总览中被选中的项目必须在模块列表中可见并默认勾选。
    - 未启动时只显示选择器、对象范围、预计调用量与「启动分析」按钮，**不得预渲染任何图形或结论**（与政策链现有的未启动态一致）；时间链不得同时出现"清单 + 图形"两套视图。
    - 点击「启动分析」后按选中的 1–3 个主体执行本模块，结果区再渲染：时间链＝每个被分析项目一条阶段链（逐项目展示，不再只渲染当前项目），政策链＝三级传导，产业链＝2.5D 关系图，公开风险＝工商档案，获客＝关系派生建议，行动＝可执行清单。
    - 模块结果按"项目 + 模块"保存（沿用 `AnalysisRunState`），切换项目不丢结果；未运行时状态为"未启动"。
3. **关注具备搜索性质。** 关注不是静态清单：它按策略对每个订阅项目执行增量复查（下一阶段 + 当前阶段的更正/终止信号），默认周期 7 天、可在关注页暂停；继续遵守既有预算规则（缓存优先、单次应用启动最多自动检查 1 个到期项目、每项目每次最多 1 次搜索）。复查取得的新证据必须回写该项目的时间链与相关模块状态；阶段只能被证据推进或更正，不能因漏搜而倒退。
4. **不得重复建设。** 时间链页的"订阅"按钮与关注页指向同一 `ProjectWatch` 记录，同一项目只允许一条订阅；两处入口必须显示同一状态。
5. **失败必须可诊断（商机雷达实机教训）。** 任何意图解析或执行失败，必须同时在**当前模块页内**显示失败态与原因，并落盘可读诊断：任务 ID、原始模型返回、解析后的字段差异、缺失字段名。当前 DSH 会话只落 `session.jsonl.zstd`，人工无法直接打开，视为不满足可诊断要求；诊断产物必须是可直接阅读的文本。
6. **雷达 criteria 基线。** 项目路由（自动识别）继续要求模型返回字段完整的最终条件，程序不用旧条件补齐；但**雷达路由**以本机 `deepRadarSearchCriteria(profile)` 为基线，模型只对用户原文明确要求覆盖的字段做覆盖，缺失字段不得导致整次任务失败；合并结果仍须通过 schema 校验。雷达失败态文案必须指出缺哪个字段，不能只说"模型没有返回完整条件"。
7. **雷达不得因"输入太笼统"停下（2026-09-15 实机教训）。** 雷达的方向由长期能力画像决定，不由本次一句话决定。只要画像的业务地域、行业、专业能力三项中任意一项非空，模型就必须输出 `opportunity` 并按画像生成 `searchQuery`，禁止返回 `clarify` 反过来追问用户"想找哪类项目"；程序侧同为兜底：此时即使模型返回 `clarify`，也按画像基线继续搜索，并把模型提示作为状态信息展示，不中断任务。只有画像三项全空时，才允许 `clarify`，并须明确指出需要先补哪一项画像字段。澄清结果必须同时显示在雷达模块页内，不能只留在左侧对话栏。
8. **雷达项目阶段筛选（2026-09-15 用户要求，字段↔路由↔落库全面实现）。** 雷达必须能让用户选择"要匹配的项目处于哪个阶段"：立项 / 采购意向 / 招标 / 开标评标 / 中标候选人 / 中标成交 / 合同签约 / 不限。实现边界：
   - **字段**：7 个既有阶段（`PROJECT_STAGE_DEFINITIONS`）＋`all`（不限），与附近招标条件栏用的是同一套枚举，不另造阶段词。
   - **落库**：作为**雷达本次搜索条件**单独保存在本机（`shiji.radar-stage-filter.v1`）。它既不写进长期能力画像（画像只描述"能承接什么"），也不读写自动识别条件栏 `OpportunitySearchCriteria`，遵守 §5.9 的雷达隔离要求。
   - **路由**：阶段进入 `deepRadarSearchCriteria(profile, targetStageId)` → `SearchPlan` 阶段关键词 → 豆包查询 → 正文阶段门禁 → 结果卡与时间链。信息流与附近招标完全一致，不建立第二套阶段逻辑；雷达默认值为 `tender`（在招、可投标）。
   - **模型不得改写**：阶段是用户在本机的确定性选择，意图层必须原样返回，程序侧 `radarIntentOverrides` 也会剥掉模型给的阶段并回填本机值——否则用户选了"中标/合同"，模型一句"招标公告"就会把方向拉回在招项目。`searchQuery` 必须体现所选阶段的检索词。
   - **"进场施工"暂不存在**：当前模型只有 7 阶段，最接近的是 `contract`（合同公告 / 已签约）。若要新增"进场施工"作为第 8 阶段，属于需求扩展，须同时改 `PROJECT_STAGE_DEFINITIONS`、阶段关键词表、正文阶段门禁与时间链口径（七阶段→八阶段），并按 9.1 重新做真实路径验收；在此之前不得在界面上提供该选项。


## 6. 来源、转载与证据分级

### 6.1 必须分别保存的维度

- `pageUrl`：用户实际看到的页面。
- `publisher`：当前页面发布者。
- `originalPublisher`：页面声明的原始发布单位。
- `originalUrl`：能找到时保存原文链接，找不到时明确为空。
- `provenanceType`：原始发布、明确转载、摘要转述、聚合、未知。
- `documentIdentifiers`：项目编号、采购编号、文号、统一社会信用代码等。
- `publishedAt/capturedAt`：原发布时间和本机获取时间。
- `contentHash`：正文或文件指纹，用于去重和判断转载内容是否一致。
- `corroboratingEvidenceIds`：能够交叉印证的其他证据。

### 6.2 分级不是网站黑白名单

| 级别 | 典型条件 | 允许用途 |
| --- | --- | --- |
| A 原始证据 | 政府、交易平台、采购人、项目业主等原始发布；主体与编号可对应 | 可直接支撑对应事实和阶段 |
| B 可追溯权威转载 | 主流媒体、权威行业媒体或高信誉商业站；明确原发布单位，关键编号、日期和内容一致 | 标记为“转载确认”，可支撑多数阶段；关键字段保留转载属性 |
| C 高质量报道/转述 | 发布者信誉较高、主体和事项明确，但原文或关键编号不完整 | 可进入报告和时间线候选，不单独形成高风险最终结论 |
| D 普通聚合线索 | 来源不明、内容残缺、无主体标识或无法追溯 | 只用于发现和继续搜索 |

站点信誉只能影响初始权重，不能替代具体页面判断。信誉表应允许本地更新，并由真实测试样本逐步形成；当前不能凭印象一次性列出完整白名单。

### 6.3 不同业务使用不同阈值

- 立项信号、行业趋势、前期商机：A、B 可确认，C 可形成带提示的候选。
- 招标、中标、合同：A 可确认；B 在原发布单位、项目编号、日期和关键内容一致时可“转载确认”；C/D 不单独推进阶段。
- 工商处罚、失信、经营异常：A 可确认；B/C 只能形成候选记录，仍需核对主体身份和有效状态。
- “未找到”“页面打不开”“模型没返回”永远不能转换成“没有该事项”。

## 7. 时间链与订阅闭环

### 7.1 用户按阶段搜索

1. 左侧选择目标阶段。
2. `SearchPlan` 生成该阶段的关键词、调用上限和缓存策略。
3. 搜索命中经过正文读取、出处追踪和证据分级。
4. 只有达到该阶段用途阈值的证据，才能使结果被标记为处于该阶段。
5. 结果卡片、详情和时间链读取同一项目及同一阶段证据。

### 7.2 用户订阅项目

1. `ProjectWatch` 保存项目 ID 和上次证据确认阶段。
2. 应用启动时先检查缓存时效；未过期不产生新付费调用。
3. 需要复查时，只搜索下一阶段及当前阶段的更正/终止信息，默认每项目最多一次搜索。
4. 新来源经过与普通搜索完全相同的出处和证据处理。
5. 新证据达到阈值才推进阶段；临时漏搜旧证据不能让阶段倒退。
6. 发现阶段变化后更新项目、时间链、报告和关注提示；历史证据继续保留。

自动跟踪不是后台服务器常驻。V1 只在应用运行期间执行，并向用户展示缓存命中、实际调用次数、检查时间和失败原因。

## 8. 数据写入与状态边界

- `SearchHit` 只增加候选来源，不改变业务结论。
- `DocumentArtifact` 只表示内容已取得或已导入，不代表内容已核验。
- `EvidenceAssessment` 决定证据可用于发现、候选还是确认。
- 时间链只由阶段证据重算；预计窗口与确认阶段分开。
- 政策强度、匹配分、跟进级别可以重算，但不得覆盖原始证据。
- 用户拖拽、对比、关注和行动只新增关系或状态，不复制底层项目数据。
- 当前候选、已归档和不感兴趣由同一个 `OpportunityCatalog` 管理。新搜索只替换当前结果集合，不覆盖归档或忽略记录；相同稳定机会 ID 再次命中时沿用隐藏状态。跨网站不同 ID 的同项目去重仍依赖后续项目合并规则，不能仅靠标题猜测为同一项目。
- 归档保留项目和证据，供用户以后恢复；不感兴趣保留项目和证据但不自动回到候选。删除是明确的本地清理动作，必须二次确认，并同步清理该机会的扩展分析状态、关注、拖拽关系、业务对象映射以及无其他项目引用的搜索证据；公开网络上的原始信息不会被删除，未来重新搜索仍可能再次发现。
- 模型输出必须经过结构校验；模型生成的引用不能在未取得对应来源时成为证据。

### 9.1 强制用户路径验收门禁

每个达到用户可操作状态的开发阶段，都必须在正常桌面生产入口、`Mock=关闭` 的情况下完成一次真实用户路径验收；布局可用开发预览补测，但开发预览不能证明业务闭环。验收至少记录：

1. **环境**：桌面版本、前后端契约版本、Mock 状态，以及 Key、网络、地图审核等外部前提是否具备。
2. **输入**：用户实际输入的自然语言，以及地区、目标单位/项目、金额、专业、阶段、时间范围和候选数等锁定条件。
3. **操作路径**：从左侧运行开始，依次点击了哪些右侧卡片、详情、扩展模块、归档/拖拽/订阅等入口。
4. **右侧结果**：首层实际出现哪些卡片；点开后出现哪些事实、缺失项、原文、附件和模块状态；无结果、未接入或失败时是否清楚说明原因。
5. **调用与缓存**：豆包、DSH、地图和其他能力的预计/实际次数，是否命中缓存，是否发生了意外连带调用。
6. **本机状态**：需要持久化的结果在刷新或重启后是否仍存在，当前项目、条件、归档、订阅和分析状态是否一致。
7. **反向路径**：至少验证一个与本轮相关的缺 Key、无结果、来源不合格、超时、依赖未完成或按钮禁用场景，确认不会回退到 Mock 或伪造结果。

阶段汇报固定采用“输入｜操作｜右侧结果｜调用/缓存｜重启/失败路径｜结论”六项短格式。没有完成上述实机路径，只能报告“代码已完成、用户验收待做”，开发清单不得勾选为完成；因天地图审核、余额或网络等外部条件无法验证时，必须明确标为“外部前提未满足”，不能把地图框架加载或单元测试当成业务通过。

## 10. 当前差距与开发顺序

### 已确认的当前差距

## 11. 最后阶段预留：创业沙盘

本模块作为识机完成现有企业商机主线后的最后开发项，当前只冻结产品边界，不安装框架、不消耗模型额度，也不阻塞第 3.2–12 项。

**2026-09-22 产品调整**：商机推演不再在当前桌面版继续开发，后续作为独立线上产品另行立项。桌面端保留一级导航入口，左栏和工作区只显示“功能开发中，敬请期待”；不再展示四步向导、选址、创业者画像、财务参数、仿真按钮或报告占位。既有本机草稿数据不主动删除，但当前界面不读取和展示。

- **产品定位**：创业沙盘是“附近机会 → 个人机会”中的旗舰能力，同时保留可进入独立全屏模块的入口；它利用用户主动填写的精力、资质、阅历、资源、人脉、渠道、性格偏好和家庭约束，结合附近真实市场信号，对候选创业项目进行模拟、淘汰和压力测试。不得把模拟结果宣传为真实成功率或确定收益。
- **产品形态**：用户只看到识机的一个完整版本和一个内置功能，不区分青年版、轻量版或外挂包。是否随安装包完整携带运行环境，要在最后阶段依据实测安装体积、Windows 兼容性和运行负担决定，不提前承诺。
- **技术边界**：沙盘引擎必须与 Electron 主程序、本地项目库和现有 DSH/SearchPort 解耦，通过稳定的本机任务接口交换结构化输入、进度和报告。这样既不要求当前建设服务器，也便于用户量和方法成熟后将其摘成独立产品；这种内部解耦不得演变成用户需要维护的多版本体系。
- **候选基座**：AgentSociety 2 仅列为优先验证对象，不在验证前写成已选定依赖。正式采用前必须完成 Windows 下 50/100/300 个模拟角色的安装、启动、取消、恢复、内存、CPU、耗时、模型调用量与结果稳定性实测；特别核对官方 Windows 安装不包含 Ray 时的大规模执行能力。若不能满足桌面交付，则只替换内部执行层，不改变上述产品入口和报告契约。
- **运行原则**：角色数量按任务复杂度动态确定，消费人群只是一个重要群体，还应保留竞争者、渠道、供应商、经营者、财务/风险与审计角色；采用分组、抽样和多轮淘汰，禁止全连接群聊。用户模型 Key 和任务数据继续只保存在本机；每次运行前展示预计调用规模，并由用户主动确认。
- **价值边界**：竞争力来自“用户画像 + 地图/政策/市场真实证据 + 候选项目生成 + 模拟规则 + 可执行验证报告”，不是来自展示智能体数量。最终报告至少包含个人适配、区域机会、消费意愿信号、资金与资源替代、竞争/渠道压力、主要失败路径，以及可停止的低成本验证实验。
