# 识机 V1：产品冻结与第一阶段开发契约（已废止）

> **状态：仅供历史参考，不得作为当前需求、开发或验收依据。** 第一阶段 Mock 原型冻结已经结束，本文包含“不接真实搜索”等过期口径。当前唯一有效的产品需求、数据流和开发清单为 [`PRODUCT_LOGIC_DATAFLOW_V1.md`](./PRODUCT_LOGIC_DATAFLOW_V1.md)；发生冲突时必须以后者为准。

## 1. 产品定义

识机是 Windows 本地安装的 AI 商机与生意工作台。用户配置自己的模型与搜索服务 Key；搜索词、结果、企业资料、证据、报告、附件和 Key 不上传识机服务器。

识机销售的是本地软件使用授权，不销售模型 Token、搜索次数或云端数据。

## 2. 已冻结架构

- 桌面端优先采用 Electron + React + TypeScript。
- 自有前端和本地业务数据为产品主体。
- DeepSeek Harness（DSH）作为可替换的本地 Agent 运行时，不使用其 Web UI，不修改其核心代码。
- 前端只能通过识机的 `AgentRunner` 契约调用本地运行时，不得导入 DSH 内部包或事件类型。
- 业务数据由识机本地存储拥有；DSH Session 只保存执行轨迹，不是业务数据库。
- 通用能力优先使用经过审查且锁定版本的插件；只为识机特有的业务 Schema、匹配规则和对象关系写薄适配。
- V1 不建设业务服务器、云端搜索、云端报告、云端数据 API、Skill 市场或用户数据采集。

## 3. 核心业务对象

- `BusinessProfile`：地址、服务范围、专业、可承接金额、项目类型等商业能力档案。
- `Task`：一次搜索、分析或核验任务。
- `SearchRequest`：本次搜索条件。
- `Opportunity`：可管理、比较、跟进的商机。
- `Company`：企业或机构。
- `Evidence`：网页、公告、PDF、截图等原始证据。
- `AnalysisResult`：时间、政策、产业、工商信用核验等分析结果。
- `Recommendation`：建议联系对象、原因和策略。
- `ActionItem`：由建议转化的行动。

对象在模块间通过稳定 ID 和关系复用，不复制多份数据。

## 4. 工作台交互

- 左侧为持续存在的任务/对话面板，保存当前任务、条件、运行过程和候选摘要。
- 右侧为动态工作区，显示结果、地图、机会、企业、证据、产业图谱、对比和报告。
- 导航栏、任务/对话栏和右侧工作区之间提供两条可拖动分隔线，宽度保存在本机；右侧工作区始终保留最低可用宽度。
- 大地图、PDF、关系图谱可进入专注或全屏模式；退出后恢复原任务和选中对象。
- 拖拽只作用于机会、企业、证据、建议等业务对象，并按对象类型限制目标模块；不允许任意“模块拖进模块”。拖动过程必须有把手、浮层和目标高亮反馈。

## 5. 模块边界

- 深度雷达：`BusinessProfile + SearchRequest -> 搜索 -> 证据核验 -> 匹配解释`，不是第二套搜索引擎。
- 附近商机：统一搜索增加地理条件，地图只是视图。
- 附近机会分为个人与企业：个人模式不能只展示 POI 热度，还要结合分层地理热点、客流时段、同业竞争、成本约束、当地有效政策与趋势信号，分别生成门店开店、摆摊/轻资产和其他趋势型创业建议；每条建议必须给出适合位置与客群、时段、依据、政策/许可前提、投入边界、风险、置信度和实地核验动作，并区分事实、推断与建议。企业模式展示附近招标主体、金额、专业和招标概述。
- 工商信用核验：公开工商信息与风险的搜索、官方核验和人工导入；“未发现”不得表述为“没有风险”。
- 产业链产生企业关系；拓客基于同一关系生成 Recommendation。
- GEO 诊断使用独立的个人/企业档案，按固定问题集比较多模型的提及、推荐、事实准确性、引用和搜索展示；模型记忆与联网搜索必须分开标记。报告只给完善建议，不代替用户实施，也不把 API 结果宣传为消费端 App 的绝对排名。
- 数据导出本期暂缓；本地对象结构先保持可扩展，不为导出格式提前增加复杂度。
- 对外云 API、云任务、云结果下载和 Skill 市场删除；本地 API 延后。
- 工程计量是另一套独立软件。识机 V1 只提供“进入工程计量/下载计量软件”入口，不称 CAD 移交，不承诺自动报价。
- 一级代理是线下推广合作流程，不开发代理登录、线上客户台账、自动归因或自动结算。

## 6. 当前交互原型范围

交付可运行、可核对完整信息架构的本地原型：

1. Electron/React/TypeScript 基础工程。
2. 固定左侧受控对话区：自然语言用于补充意图，地址、范围、专业、金额、项目类型和时间窗口由控件锁定，模型不得擅自修改。
3. 动态右侧工作区：机会总览、深度雷达、附近机会、GEO、时间链、政策链、产业链、企业公开风险、获客建议、行动指南、对比和关注任务均有独立可切换视图。
4. 产业链使用轻量 2.5D 节点图，支持节点拖动、画布平移和缩放；不是重型三维引擎。
5. 机会、企业、证据、获客建议和行动通过稳定 ID 复用；机会对象可以拖入重点跟进、对比篮和行动清单，拖放关系保存在本机。
6. 能力中心展示内置或可安装能力，不包装成线上 Skill 市场。
7. 工程计量只提供独立软件下载入口；一级代理只展示线下合作、支付凭证和人工结算流程。
8. 使用本地演示数据和 Mock `AgentRunner` 后端验证页面、对象关系和交互，不伪造真实搜索或 DSH 对接。
9. 设置页只展示模型与搜索服务配置槽位，不保存真实密钥。
10. 保留原有冷色视觉，并提供一套暖色主调的明亮综合色主题；用深蓝紫建立结构、珊瑚橙突出主操作、青绿和蓝色区分信息状态。切换选择保存在本机，主题不得改变业务数据和工作区状态。

## 7. 第一阶段明确不做

- 不接真实模型、搜索、工商网站、OCR或地图 SDK。
- 不接易支付，不写入任何真实商户信息或密钥。
- 不建设云端数据库、登录、注册、积分或订阅后台。
- 不实现工程计量软件调用协议，只保留待配置的下载入口。
- 不开发重型真 3D、无业务含义的任意拖拽或插件市场；允许与业务对象绑定的轻量 2.5D 图谱和拖放管理。
- 不实现数据导出。
- 不为“以后可能需要”增加微服务、消息队列、通用工作流引擎、复杂权限系统或多端适配层。

## 8. 验收证据

- 项目可安装依赖并启动开发环境。
- 主工作台在桌面尺寸正常显示，左侧任务上下文在右侧视图切换时不丢失。
- 填写商业能力档案后，可由 Mock Harness 生成候选机会并打开时间、政策、产业、公开风险、获客和行动等层级。
- 地图列表与机会详情引用同一个 Opportunity ID。
- 左侧对话及锁定条件在右侧切换各模块时保持不变。
- 产业图节点可拖动，画布可平移和缩放；对象拖入管理区时不复制原始机会数据。
- 两条分隔线可调整三栏宽度，刷新后恢复；导航汉字不得因窄栏逐字竖排。
- 附近机会可切换个人与企业模式。个人热点和“附近我能做什么”建议卡可进入门店、摆摊或趋势创业详情报告；企业招标卡可进入通用招标详情报告。报告必须支持返回原列表且不丢失左侧任务上下文；Mock 阶段也要完整模拟摘要、依据/证据、政策或许可边界、风险和下一步核验层级。
- 拖动对象时显示明确的移动浮层和可投放/不可投放状态，投放结果刷新后仍存在。
- 页面刷新后至少恢复当前任务、视图和选中对象的模拟状态。
- 类型检查和已有测试通过；没有真实密钥、云端数据库或未授权网络调用。

## 9. 工程约束

- 一次只交付一个已定义阶段。
- 修改前检查现有实现和用户改动。
- 优先复用成熟库和插件，不重写通用能力。
- 不做无关重构，不提前抽象，不制造重复数据源。
- 无测试或可观察证据时不得宣布完成。
- 不自动部署、发布、提交远程仓库或接入外部付费服务。
