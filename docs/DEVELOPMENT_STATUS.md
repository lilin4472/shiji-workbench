## 2026-09-15（四）· 天地图“底图未加载”失败态收口（0.2.5 / 契约 11）

用户实机反馈附近招标页只显示“当前不显示示意地图，修正网页端 Key 或授权来源后可重新加载”。代码复核后确认有两个问题：

## 2026-09-15（十二）· 紧急热修：总览拖不进任何桶（effectAllowed / dropEffect 不兼容）

用户实机反馈：「现在总览页面无法拖入任何项目」。

根因（上一轮（十一）改动引入的回归）：`startObjectDrag` 一直把 `dataTransfer.effectAllowed` 设为 `'link'`，而（十一）为消除"红圈斜杠禁止光标"在对象管理栏 `onDragOver` 里强制 `dataTransfer.dropEffect = 'copy'`。按 HTML5 DnD 规范，`dropEffect` 必须属于 `effectAllowed` 允许的集合；`effectAllowed='link'` 不允许 `'copy'`，浏览器据此判定该落点不可用——表现为光标禁止、`drop` 事件根本不触发，三个桶全部拖不进去。

修复（两处取值统一为 `copy`，语义上也更准确：拖入管理区只是写入一个引用，不移动原对象）：

- `src/components/Workspace.tsx` `startObjectDrag`：`effectAllowed` 由 `'link'` 改为 `'copy'`，并补注释说明两侧必须一致。
- `src/App.tsx` 对象管理栏 `onDragOver`：去掉 `if (draggedObject)` 条件，**始终**设置 `dropEffect = 'copy'`，避免 React 状态更新时序造成落点被判不可用。

### （十二）补充：拖放仍失败的第二个机制与兜底（同轮）

用户复验后反馈「九康二路仍拖不进去，且拖动过程仍是禁止光标」。复查确认存在**第二个、更隐蔽的机制**（与 effectAllowed/dropEffect 无关）：

- `App.tsx` 里那个 `window` 级 `pointerup` 监听（原本用于取消指针拖拽）在**鼠标松开瞬间先于 `drop` 执行**，把 `draggedObject` 置空并触发重渲染；随后 `drop` 回调执行到的是新一次渲染的 `commitDrop`，`const object = draggedObject` 已是 `undefined`，函数第一行 `if (!object) return` **静默返回**——表现为"落下什么都没发生"，且没有报错、没有提示。
- 且落点判定只挂在三个 `<button>` 上，落在按钮之间的空隙/标签上时浏览器按"不接受"处理，正是"禁止光标"。

同轮修复：

- `cancelPointerDrag` 增加判断：`pointerup` 落在 `.drop-dock` 内时**不清空拖拽状态**，交给 `drop` / `onPointerUp` 处理。
- `commitDrop(bucket, explicit?)` 支持显式传入被拖对象（为后续从 `dataTransfer` 取载荷留好入口）。
- `.drop-dock` 容器增加 `onDragOver`（`preventDefault` + `dropEffect='copy'`）与 `onDrop` 兜底：用 `closest('[data-bucket]')` 解析落点；三个按钮补 `data-bucket` 属性，空隙/标签上也能命中。
- 总览拖拽载荷补 `opportunityId: item.id`（此前只有 `id`，拖未选中的卡片会把订阅挂到"当前选中项目"上）。

工具侧经验（供后续接手参考）：本仓库文件为 CRLF，`str_replace` 的 `old_str` **带前导缩进的整行匹配会失败**，应改用"不含缩进的最小唯一片段"作为锚点，多行替换改用"行号插入 + 单行替换"组合。

用户反馈（2026-09-18）：时间链 / 政策链 / 产业链 / 公开风险（以及同一结构、尚未接入真实执行器的获客与行动）对象行上的「移出」按钮点下去像没反应项目既没消失，界面也没有任何变化。

**根因不是按钮没接上，而是接错了动作，并且移空之后又被兜底带了回来**：

1. **接错了动作**：模块页对象行把 `onRemoveFromScope` 接到了总览复选框用的 `toggleAnalysisSelection`，那是"勾选 / 取消勾选"语义不在集合里就**加进去**。当对象来自"未勾选时退回当前选中项目"这条兜底路径时，点「移出」等于把它**勾进**分析范围（实测：`shiji.analysis-selection.v1` 从 `[]` 变成 `["verify-remove-1"]`），界面当然一动不动。
2. **移空后被兜底带回**：即使走的是正常删除，移掉最后一个项目后 `scopeCleared` 仍是 false，模块页按 `analysisSelection.length > 0 ?  : (scopeCleared ? [] : [selected])` 立刻退回"当前选中项目"，刚移走的项目下一秒又出现（实测：结果卡 2  1  又是 1）。
3. **两处同源**：总览「清空」没有置 `scopeCleared`（清空后模块页仍挂着当前项目）；`AnalysisNotStarted` 大标题取 `items[0]?.opportunity ?? fallback[0] ?? selected`，对象被移空时仍显示 `selected` 的项目名，等于又把移走的项目挂回页面上。
4. `App.tsx` 里其实早就写好了 delete 语义的 `removeFromAnalysisScope`（移空时会把 `scopeCleared` 置 true，注释也写明了"否则「移出」看起来没用"），但**全项目没有任何调用方**一段定义了没接线的死代码；这轮把它接上。

**修改（4 个文件）**：

- `src/App.tsx`：新增传参 `onRemoveFromScope={removeFromAnalysisScope}`；「清空分析范围」同步 `setScopeCleared(true)`。
- `src/components/Workspace.tsx`：`Props` 声明并解构 `onRemoveFromScope`；时间链 / 政策链 / 产业链 / 公开风险结果页与未启动面板 + 获客共 **9 处**「移出」统一改接 `onRemoveFromScope`；`AnalysisNotStarted` 大标题改为随对象数走（0 个对象＝"尚未选择项目"）。
